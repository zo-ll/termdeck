**Findings, ordered by priority**

1. **[P1] `termctl --paste` can execute payload text as a shell command.** [src/session/input.rs:48](/home/az/projects/termdeck/src/session/input.rs:48), [src/session.rs:436](/home/az/projects/termdeck/src/session.rs:436). `encode_paste` wraps arbitrary control-request text without rejecting an embedded `ESC [ 201 ~`. Its comment assumes the outer keyboard parser has already removed that possibility, but socket paste requests bypass that parser. In an isolated Bash pane with bracketed paste enabled, a paste beginning with that terminator followed by `printf AUDIT > '/tmp/.../paste-executed'` and a newline executed the command. The response reported success and the marker contained `AUDIT`. This requires already-authorized input (`--force` or the input gate); it does not establish a permissions bypass. It breaks the distinction between pasting content and executing content. Validate the paste payload at the shared encoding boundary and refuse embedded terminators atomically. Add a socket-to-real-shell regression proving that the payload cannot execute.

2. **[P1] Small terminal sizes crash the interface and end the session.** [src/ui/picker/sheet.rs:115](/home/az/projects/termdeck/src/ui/picker/sheet.rs:115), [src/ui/deck.rs:1376](/home/az/projects/termdeck/src/ui/deck.rs:1376), [src/ui/deck.rs:1413](/home/az/projects/termdeck/src/ui/deck.rs:1413). The sheet calls `clamp(11, area.height.saturating_sub(2))`; below 13 rows its bounds are inverted, which always panics. Open `Ctrl+g a`, then shrink to 12 rows: the actual application aborts. The ordinary deck also uses unchecked subtractions for content size and right-slot placement. The debug boundary sweep reproduces those panics at small sizes, including ordinary widths at heights 4–5. Establish minimum renderable geometry before drawing, and provide a safe fallback for both the deck and overlays. Cover resize transitions in addition to fixed-size snapshots.

3. **[P1] Bounded PTY queues do not bound terminal-parser memory.** [src/engine/vt.rs:81](/home/az/projects/termdeck/src/engine/vt.rs:81), [src/engine/vt.rs:261](/home/az/projects/termdeck/src/engine/vt.rs:261). Output is fed directly to VTE, whose resolved `std` feature stores OSC payloads in an uncapped vector. Feeding an unfinished `ESC ] 0 ;` in 4 KiB chunks into a 2×2 terminal with one history line raised RSS from 2,784 KiB to 11,048 KiB after 8 MiB, and 19,304 KiB after 16 MiB. Separately, a single cell retained 65,537 Unicode scalars / 131,073 bytes after repeated combining marks. The adapter copies that accumulated text into frames. A child can exhaust session memory despite fixed viewport, history and transport limits. Bound both control-string retention and per-cell combining sequences, preserving normal Unicode and parser recovery. A bounded input-side OSC scanner for notifications alone does not solve this output-side problem.

4. **[P1] Shutdown skips surviving descendants that left the original session.** [src/engine/native.rs:537](/home/az/projects/termdeck/src/engine/native.rs:537), [src/engine/pty.rs:338](/home/az/projects/termdeck/src/engine/pty.rs:338). `request_shutdown` snapshots descendants, including a child that called `setsid`, but the force phase runs only if the original process group or session remains alive. When the original parent exits on HUP/TERM, the detached child no longer satisfies either condition, so `kill_descendants` is never reached. A real Python fork/setsid probe remained alive after `EngineCommand::Shutdown` returned; it was still parented to the owned process before shutdown began, so it was within the snapshot's intended coverage. Include validated snapshot survivors in both the force decision and completion checks, or always sweep the validated snapshot after grace.

5. **[P2] PID-reuse protection does not cover the first signals or descendant capture.** [src/engine/pty.rs:369](/home/az/projects/termdeck/src/engine/pty.rs:369), [src/engine/pty.rs:419](/home/az/projects/termdeck/src/engine/pty.rs:419). This finding is source-confirmed; PID reuse was not forced experimentally. An exited pane retains its transport and numeric process-group ID after its shell is reaped. Later close, respawn or session shutdown snapshots descendants and sends HUP/TERM to that ID without checking the recorded shell start time. The force path sends group SIGKILL before the reuse check inside `kill_session`. If the number now belongs to an unrelated process group, that group can be signalled and its descendants newly captured as owned. Apply identity validation before every ownership expansion or signal, and retire completed transport ownership. Also avoid re-entering shutdown from `NativeEngine::drop` after an explicit completed shutdown.

6. **[P2] Unicode case-insensitive filtering can panic on valid repository names.** [src/ui/picker/state.rs:657](/home/az/projects/termdeck/src/ui/picker/state.rs:657), [src/ui/picker/render.rs:565](/home/az/projects/termdeck/src/ui/picker/render.rs:565). `match_at` computes byte offsets in a lowercased string, then the renderer slices the original string using those offsets and the original query byte length. Unicode lowercasing can change byte length. Rendering repository name `İx` with query `x` reproduces `end byte index 4 is out of bounds for string of length 3`. Map normalized matches back to valid original-string boundaries rather than reusing normalized byte offsets. Test expanding case mappings and multibyte queries.

7. **[P2] The required test gate depends on being launched inside Termdeck.** [src/bin/termctl.rs:418](/home/az/projects/termdeck/src/bin/termctl.rs:418), [.github/workflows/ci.yml:60](/home/az/projects/termdeck/.github/workflows/ci.yml:60). The literal-notification parser test supplies neither `--socket` nor an injected environment; it unwraps a parse that falls back to `TERMDECK_SOCK`. With that variable absent, the required all-targets suite fails at line 423. Running that exact test with an inert, nonexistent socket path in the environment passes: no server is needed. The workflow does not set the variable, so its main test step is also exposed to this deterministic failure. Give the test an explicit socket before `--`, or inject a parser environment. Verify the gate with Termdeck-specific environment variables unset.

8. **[P2] The client timeout excludes connection establishment.** [src/ctl/mod.rs:610](/home/az/projects/termdeck/src/ctl/mod.rs:610). A blocking `UnixStream::connect` happens before the deadline is created. A Unix listener whose backlog is full makes `termctl status` block indefinitely rather than respecting the advertised bounded call. A disposable listener with backlog 1 and two queued connections kept the command blocked beyond 4 seconds; the configured client timeout is 2 seconds. Use a nonblocking connection and one absolute deadline covering connect, write and read. Existing timeout tests only cover servers that have accepted the connection.

9. **[P2] The Bash notification hook overwrites the status seen by existing prompt hooks.** [src/engine/shell_hook.rs:29](/home/az/projects/termdeck/src/engine/shell_hook.rs:29), [src/engine/shell_hook.rs:39](/home/az/projects/termdeck/src/engine/shell_hook.rs:39). `__td_prompt` is prepended to both scalar and array `PROMPT_COMMAND`, but returns the status of its own condition/printf instead of preserving the previous command's status for the next hook. An interactive Bash probe with an existing `PROMPT_COMMAND` printing `$?` reported `USER_STATUS=0` after `false`, including with `TERMDECK_NOTIFY=none`. Error indicators and prompt integrations therefore see the wrong result. Preserve the captured exit status across every return path and test an existing prompt hook's observed status, not merely that the hook still runs.

10. **[P2] Literal help text is swallowed as successful help output.** [src/bin/termctl.rs:238](/home/az/projects/termdeck/src/bin/termctl.rs:238). `help_for` tracks value-taking options but ignores a pending `takes_value` after walking the preceding tokens. `termctl --socket /tmp/nonexistent.sock input one --text --help` prints the input help page and exits 0, without sending input or attempting a connection. The same problem affects `--paste`, `--keys` and values ending in `-h`. Parse help with option-value awareness; a token consumed as a value must stay a value. Add literal-value tests against the binary's help prepass.

11. **[P2] Folder discovery can generate duplicate terminal identities.** [src/cli/mod.rs:289](/home/az/projects/termdeck/src/cli/mod.rs:289), [src/cli/mod.rs:343](/home/az/projects/termdeck/src/cli/mod.rs:343). A workspace containing repositories `frontends/web` and `fe-web` discovers two terminals both named `fe-web`. The native engine then rejects the entire workspace with `native engine terminal identities must be unique`. This was reproduced through the public discovery and spawn APIs. Apply one deterministic identity allocator across grouped and direct discovery results, as the picker/runtime-add paths already do.

12. **[P2] Bare `termctl zoom` mutates state despite help describing a read.** [src/bin/termctl.rs:286](/home/az/projects/termdeck/src/bin/termctl.rs:286), [src/session.rs:397](/home/az/projects/termdeck/src/session.rs:397). Both general and command help describe reading the zoom state when no option is present. Dispatch instead toggles when `on` is `None`. An isolated live session changed from `zoom=false` to `zoom=true` after a bare zoom request. An agent following the help can therefore change the user's layout while inspecting it. Resolve the documented contract explicitly: either make the bare request read-only, or accurately advertise it as a toggle and point readers to `status`. The older API design describes toggle behavior, so this is a contract/documentation mismatch rather than evidence that toggling was never intended.

13. **[P2] The panic guard itself panics during unwinding.** [src/session/outer.rs:86](/home/az/projects/termdeck/src/session/outer.rs:86). `PanicGuard::drop` always calls `panic::take_hook` and potentially `panic::set_hook`. Rust forbids changing hooks from a panicking thread. The live resize crash produced the original geometry panic, then `cannot modify the panic hook from a panicking thread`, then `panic in a destructor during cleanup`, and exited by `SIGABRT`. Terminal restoration happened earlier and was verified, but this guard converts an ordinary unwind into a second panic/abort. Make destruction safe during unwinding and test the panic path in a subprocess.

**Dependency and security observations**

The scan used RustSec database commit `5a0ebedfe8bdd2e295b171f4162f8c977bcad9a5`, last updated 2026-09-02. Its three warnings are:

- `lru 0.12.5`, introduced by `ratatui 0.29.0`: [RUSTSEC-2026-0002](https://rustsec.org/advisories/RUSTSEC-2026-0002.html), iterator soundness; and [RUSTSEC-2026-0253](https://rustsec.org/advisories/RUSTSEC-2026-0253.html), panic safety in `pop`. Versions fixing the individual issues are respectively `>=0.16.3` and `>=0.18.2`.
- `paste 1.0.15`: [RUSTSEC-2024-0436](https://rustsec.org/advisories/RUSTSEC-2024-0436.html), unmaintained.

These are actual lockfile matches, but exploitability in Termdeck was not established. The inspected Ratatui layout-cache source does not call the affected `iter_mut` or `pop` APIs. Treat this as dependency maintenance and reachability triage; zero vulnerability-class findings does not erase informational soundness warnings. The direct `serde_yaml` dependency also resolves to `0.9.34+deprecated`, although this scan did not emit a serde_yaml advisory.

The socket server has useful protections: same-UID peer checks, private directory modes, bounded pending peers, bounded request and serialized-response sizes, and nonblocking reply writes. One remaining hardening concern is [socket_directory](/home/az/projects/termdeck/src/ctl/mod.rs:674): it follows existing symlinks and chmods their targets without verifying the directory identity. A disposable symlink probe changed an unrelated target directory from 0755 to 0700. A cross-user exploit was not established; Linux symlink protections and parent-directory ownership affect reachability.

**Architecture, CI and acceptance limits**

The shared contracts use owned application types and do not expose Ratatui, Alacritty or PTY implementation types. Engine and session composition preserve the intended broad separation. No application integration with tmux, OpenMux, a daemon or session persistence was found. Horizon-specific material remains configuration/reference material. No ownership-area implementation changes were made during this audit.

The CI workflow has a pinned toolchain, locked dependency resolution, bounded jobs, installation of optional shells, and a narrow retry for one shutdown test. Dependency advisory failures are intentionally nonblocking. Informational warnings also leave cargo-audit successful, so the workflow's failure-only summary does not surface those warnings outside its detailed scan log. The live workflow was not run remotely during this audit.

Zsh and Fish are absent in this environment. Their compatibility tests can return successfully by skipping their bodies, so the 408 passing library tests are not local evidence of either shell's behavior. This audit exercised Bash, Linux PTYs, temporary Unix sockets and termios restoration. It did not certify WSL, Windows Terminal, interactive Vim/Codex compatibility, visual fidelity to every HTML reference screen, release-mode coverage of every arithmetic boundary, or long-duration load. The 1.2% CPU result describes one 10-second local sample, not the documented WSL acceptance environment.

`COORDINATION.md` reports an older green baseline and retains decisions mentioning Crossterm and excluding mouse forwarding, while the current plan describes the custom backend/decoder and alternate-screen wheel forwarding. `docs/WSL_ACCEPTANCE.md` explicitly records that the manual WSL pass has never been recorded. Historical review counts and closed workstream claims should not substitute for current verification. Remote issue status was not audited.
